skill是什么？如何编写？

从0到1，手把手教你写一个属于自己的AI Skill

你离「让AI替你干活」只差一个文件夹的距离
你有没有这样的经历。
每天打开AI对话窗口，输入同样的指令。”用Python写一个爬虫，加异常处理，输出CSV格式”。”帮我review这段代码，检查安全性、性能、边界情况”。”按这个模板生成周报，数据来源是上周的销售表”。
你复制粘贴同一段话。一遍，又一遍。
有没有办法让AI记住你的工作方式，下次只说一句”帮我review”它就自动执行整套流程？
有。Skill。

一、Skill是什么？先搞懂三件事

1.1 一个文件夹，让AI学会新本领

Skill的官方定义：一种给AI Agent增加能力和专业知识的标准化方式。
翻译成人话：你把你重复做的工作写成一本操作手册，放进一个文件夹。AI需要的时候，自己翻开手册照着做。
一个Skill就是一个文件夹：

核心只有 SKILL.md 这一个文件是必需的，其他都是锦上添花。

1.2 它和普通提示词有什么区别？

很多人问：我不就是把提示词写进文件里吗？有什么区别？
区别大了。

对比项 普通提示词 Skill
存储方式 每次复制粘贴 存成文件，一次编写永久使用
触发机制 手动输入 AI自动判断何时使用
上下文占用 每次对话都占 平时不占，需要时才加载
可复用性 仅限当前对话 跨项目、跨工具、跨团队
版本管理 无 可git管理，团队共享
Skill = 可复用的过程性知识包。

1.3 什么场景适合写Skill？

一个简单的判断标准：同一件事你让AI做了两次以上，就该写成Skill。
常见场景：

  • 代码审查流程（每次都要说”检查安全性、性能、边界情况”）
  • 周报/月报生成（固定的数据源+固定的模板）
  • 项目初始化（创建目录、配置文件、依赖安装）
  • 文档生成（API文档、变更日志、README）
  • 代码规范检查（团队约定的代码风格、命名规则）

四、写好SKILL.md的核心技巧

4.1 description是命门

description是AI判断是否使用Skill的唯一依据。写得好不好，直接决定Skill能不能被触发。
错误写法：

太模糊，AI不知道什么时候用。
正确写法：

具体、可判断、包含触发关键词。

4.3 渐进式披露

把最重要的指令直接写在SKILL.md里。深度内容放到references/目录，需要时再加载。

4.4 单一职责原则

一个Skill只做一件事。不要写一个”万能Skill”。

  • ❌ super-helper（什么都能干，什么都干不好）
  • ✅ code-review-helper（专注代码审查）
  • ✅ weekly-report-generator（专注周报生成）
  • ✅ api-doc-writer（专注API文档）

终极来源：自己写

全网最好用的Skill，永远是你自己写出来的。因为只有你最清楚自己的工作流程、业务逻辑和团队规范。

七、写在最后

Skill的出现，让AI从”问什么答什么”进化到”教一次就记住”。
你不需要成为编程高手，不需要懂复杂的AI原理。你只需要把你重复做的工作，写成一份清晰的操作手册，放进一个文件夹。
这就是Skill。
下次当你又准备复制粘贴同一段话给AI时，停下来想一想。
这件事，值不值得写成Skill？
答案大概率是：值得。
